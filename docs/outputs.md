# Outputs

Every alert can reach several outputs at once. A failing output is logged and
does not block the others.

## Notification channels

| Output | Configuration | Notes |
| --- | --- | --- |
| Mattermost | `MATTERMOST_WEBHOOK_URL` | Three coloured attachment sections. |
| Slack | `SLACK_WEBHOOK_URL` | Three coloured attachments, truncated at 3000 characters each. |
| Discord | `DISCORD_WEBHOOK_URL` | Three coloured embeds. |
| IRC | `IRC_HOST`, `IRC_CHANNEL`, `IRC_PORT`, `IRC_TLS`, `IRC_NICK`, `IRC_PASSWORD` | TLS 1.2, certificate verification, message splitting. |
| Email | `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY`, `SMTP_USER`, `SMTP_PASSWORD`, `EMAIL_FROM`, `EMAIL_TO` | Plain text plus an HTML body with a coloured banner and section blocks. |
| WhatsApp | `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_TO`, `WHATSAPP_API_VERSION` | Meta Cloud API; free-form text only inside the 24-hour window. |
| Telegram | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Bot API; messages split at 4000 characters. |
| Desktop | `DESKTOP_NOTIFY=true` | `notify-send` on Linux and FreeBSD, `osascript` on macOS. |
| RSS | `RSS_FEED`, `RSS_TITLE`, `RSS_LINK`, `RSS_MAX_ITEMS` | Atomically updated RSS 2.0 file. |

Enable any combination. `watch.py check` prints the active channels;
`watch.py test-webhook` sends to all of them.

## RSS feed

```bash
RSS_FEED=~/.local/state/opencode-spend-watch/feed.xml
RSS_TITLE="OpenCode Spend Alerts"
RSS_LINK="https://example.internal/feed.xml"
RSS_MAX_ITEMS=100
```

The file is created on the first alert and rewritten atomically after each
one. It keeps the newest `RSS_MAX_ITEMS` entries.

### Serve it locally

```bash
cd ~/.local/state/opencode-spend-watch
python3 -m http.server 8080 --bind 127.0.0.1
```

Subscribe to `http://127.0.0.1:8080/feed.xml`.

### Serve it with nginx

```nginx
location = /opencode-feed.xml {
    alias /home/YOUR_USER/.local/state/opencode-spend-watch/feed.xml;
    default_type application/rss+xml;
    add_header Cache-Control "no-cache";
}
```

Protect the location with the same authentication as your internal dashboard.
The feed contains spend amounts and model names.

### Serve it from Nextcloud

Put `RSS_FEED` on a synced directory, or point it at a path served by
Nextcloud/your static host. Nextcloud clients can subscribe to the public share
URL; the file format is ordinary RSS 2.0.

## JSONL audit log

```bash
ALERT_LOG=~/.local/state/opencode-spend-watch/alerts.log
```

One JSON object per delivery attempt:

```json
{"time":"2026-11-09T00:00:00+00:00","kind":"threshold","text":"**OpenCode spend ...","channels":[{"name":"mattermost","ok":true,"error":null}]}
```

The file rotates to `alerts.log.1` at 5 MB. Inspect failures with:

```bash
jq 'select(any(.channels[]; .ok == false))' alerts.log
```

## Console output

`watch.py poll` prints one line per cycle. `watch.py report` prints the full
message without sending it. `watch.py check` prints the active channels,
provider status, and the resolved alert log.
